# Наблюдение за пилотом фазы A

Цель пилота — проверить самостоятельность учебного цикла, понятность требований
и сохранение работы. Это не экзамен ученицы. Фаза A реализована, но пилот на
Windows нельзя считать готовым: безопасные операции требуют
`SecureDirectoryStream`, обычно отсутствующего у стандартного Windows provider.
Установка и `--version` сами по себе не проверяют эту возможность. Native smoke
Windows/Linux ещё не выполнен; используйте [матрицу evidence](../testing/phase-a-installation-smoke.md).

Проводите первую сессию на подтверждённой системе и обычном локальном файловом
хранилище. Подготовьте JDK 26, Git, установленный CLI и офлайн-кеш заранее по
[README](../../README.md). Проверьте сеть отдельно только если ученица хочет
публиковать проект. Не объясняйте внутреннюю архитектуру CLI и не показывайте
тестовые реализации из репозитория. Все наблюдения остаются в локальных заметках;
CLI не собирает телеметрию, личные данные или ответы для отправки.

Перед стартом запишите дату, ОС/build, shell, версии `java`, `javac`, Git и CLI,
способ установки и наличие подготовленного кеша. Не записывайте токены, URL
частных репозиториев или абсолютные личные пути. Согласуйте остановку наблюдения
и способ хранения заметок. Отделяйте активное время решения от установки,
перерывов и проблем среды.

Попросите ученицу создать отдельный рабочий каталог через `start`, прочитать
вывод и назвать следующий полезный шаг. Затем наблюдайте один и тот же цикл
для уроков 1–4: требование, `check`, собственное изменение, повторная проверка,
просмотр diff, локальный commit, reflection и `next`. Не давайте готовые ответы
на reflection и не исправляйте код молча. Фиксируйте каждую помощь дословно или
короткой нейтральной формулировкой и отмечайте, кто её инициировал.

Для каждого урока заполните одну строку:

| Урок | Активные минуты / паузы | Категории и повторения ошибок | Подсказки: число / максимум 0–3 | Вмешательства | Следующий шаг назван самостоятельно? | Объяснение reflection / теста |
| --- | --- | --- | --- | --- | --- | --- |
| 1: диагностика | | | | | | |
| 2: координата | | | | | | |
| 3: граница поля | | | | | | |
| 4: состояние | | | | | | |

После неправильного reflection отметьте, помогла ли адресная обратная связь.
После правильного выбора задайте открытый вопрос о причине ответа: запись
выбора проверяет распознавание, а не качество объяснения. В уроке 3 спросите:
«Какую конкретную ошибку обнаружит твой аналогичный тест?» Изменённые байты,
включая whitespace, не доказывают понимание; прочитайте утверждения вместе с
ученицей после её самостоятельного объяснения.

Между двумя уроками предложите остановиться. Закройте терминал, откройте новый
вложенный каталог проекта и попросите продолжить через `status`. Запишите,
сохранились ли текущий урок, собственные файлы и уровень подсказки; нужна ли
была ручная помощь. Повторные `start`/`check` должны сохранять валидное состояние.
Повторный `next` после перехода относится уже к новому уроку, а не повторно
применяет прежний ответ. Если виден pending journal, используйте штатное
подтверждённое восстановление; не удаляйте метаданные для обхода ошибки.

Отдельно запишите Git/GitHub friction: первый commit, выбор файлов, понимание
dirty worktree, новый commit для следующего урока, origin/upstream, создание
пустого публичного репозитория и вход штатным способом GitHub. Отсутствие сети
или публикации не является провалом урока. После финального `next` проверьте,
заметила ли ученица совет закоммитить терминальные метаданные. Если используется
локальный clone, переносите только commit-историю и готовьте кеш/JDK отдельно.

После сессии спросите, что было непонятно, какие сообщения были шумом и как
ученица выбирала следующий шаг. Подсчитайте долю уроков без прямой помощи,
вмешательства и повторные ошибки на урок, уровни подсказок и успешность resume.
80% самостоятельных уроков — ориентир интерпретации маленького пилота, а не
оценка ученицы или статистически доказанная эффективность. Если большинство
уроков требует объяснения наставника, остановите производство следующего
контента и исправьте цикл. Пилот не подтверждает безопасность против намеренно
враждебного кода: Gradle/game workers имеют права локального пользователя.
