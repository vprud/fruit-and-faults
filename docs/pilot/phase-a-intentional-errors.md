# Намеренные ошибки для наблюдателя

Используйте отдельный временный рабочий каталог или локальный clone с сохранённой
историей. Перед каждой пробой сохраните исходное состояние и покажите ученице,
какой файл будет изменён. Не применяйте эти пробы к единственному экземпляру
работы. После записи результата восстановите только свой экспериментальный
diff обычным редактором или из явно выбранной сохранённой копии; не удаляйте
проект, метаданные или пользовательские изменения. Здесь нет готовых решений
и правильных ответов на reflection.

Все обычные ошибки должны давать «ожидалось → получено → дальше» без stack
trace, секретов и абсолютных личных путей. `check` не изменяет прогресс.

| Проба / подготовка | Ожидаемая категория и код | Наблюдаемый результат |
| --- | --- | --- |
| Первый `check` в новом уроке 1 | Компиляция, 4 | Указана строка learner source; тесты ещё не выполнялись. |
| В отдельной сохранённой копии измените публичный результат уже компилирующегося кода так, чтобы он противоречил видимому тесту | Видимый тест, 4 | Понятно, какой тест/локальный report читать; это не ошибка компиляции. |
| Уберите один immutable test из экспериментальной копии | Отсутствующий артефакт, 1 | `check` остановлен до wrapper; файл не восстановлен молча. |
| Измените immutable test в экспериментальной копии | Конфликт integrity, 3 | Изменение отличено от отсутствия; progress/manifest не легализуют edit. |
| В открытом уроке 3 добавьте только пробелы/пустые строки к исходному analogous template | Видимый тест, 4 | Байты признаны изменёнными, whitespace назван явно, понимание не заявлено; исходное упражнение продолжает падать. |
| Уберите обязательный learner source | Отсутствующий артефакт, 1 | Есть относительный путь и действие по явному восстановлению. |
| После правильного check оставьте tracked edit или новый untracked файл и вызовите `next` с выбранным ответом | Незавершённая работа / Git gate, 1 | Ответ не сохранён, следующий урок не открыт; рекомендованы status/diff/commit. |
| Выполните первый `next` до локального commit либо следующий урок без нового commit | Git gate, 1 | Требуется собственный новый commit, exact commit message не навязывается. |
| Перед открытием урока 2 создайте и самостоятельно закоммитьте файл на одном из путей, показанных будущим preview | Конфликт имени, 3 | Чистая Git worktree проходит gate; чужой target сохранён и disclosure не начат. Не показывайте содержимое будущего упражнения. |
| Сохраните копию progress, затем замените только экспериментальный `progress.json` на некорректный JSON | Конфликт сохранённого состояния, 3 | status/check/hint/list/next/start сохраняют bytes; нужен явный repair/restore. |
| В экспериментальном progress укажите `formatVersion: 2` | Неподдерживаемое будущее состояние, 3 | Файл не мигрирован и не перезаписан. |
| Выполните `next --yes` в активном уроке без answer | Usage, 2 | Только дешёвое чтение состояния; нет проверки/записи. Завершённая route допускает эту команду. |

Timeout (5), interruption (5, сохранённый interrupt flag), internal validator
failure (10) и каждый durable disclosure boundary проверяются автоматически
через явно помеченные детерминированные seams. Не добавляйте в learner-код
вечные циклы, реальные sleeps, `System.exit` или опасные процессы ради живой
демонстрации. Запустите `./gradlew :app:test --tests 'org.fruitandfaults.journey.*'`
из source repository (`.\gradlew.bat` на Windows после устранения provider blocker).
Эти пробы проверяют реальные state/files/Git/CLI adapters, а управляемая внешняя
граница даёт timeout/cancellation/internal exception без ожидания 90 секунд.
Public-behavior worker не является OS sandbox.

Для stop/resume остановитесь после собственного edit или hint и запустите
`status` из вложенного каталога. Для повторения вызовите `start` на том же
каталоге и повторите `check`: files/progress не должны дублироваться. После
терминального завершения повторите `next --yes`: записанное состояние сохраняется.
Тест append-only continuation использует доверенный test-only урок 5; текущий
релиз не содержит Phase B и не раскрывает этот fixture ученице.

Отмечайте не только code/category, но и способность ученицы назвать следующий
полезный шаг, сохранить свои изменения и объяснить, почему проверка упала.
Если отсутствуют secure directory handles, остановите пилот на этой файловой
системе: успешная установка не устраняет runtime blocker. Не обходите его
ослаблением проверки symlink/ownership.
